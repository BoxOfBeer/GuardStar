# Открытый плейтест (чеклист хостинга)

Цель: один общий мир, без почты — вход по коду доступа. Ниже — минимальный набор перед тем, как звать игроков.

## 1. Развертывание БД и схемы

1. Выделите отдельный инстанс PostgreSQL и переменную `DATABASE_URL`.
2. **Обязательно** выполните миграции:

```bash
cd server
python -m alembic upgrade head
```

3. Для плейтеста/прода отключите авто-патч схемы при старте приложения:

```env
GUARDSTAR_DB_SAFETY_NET=false
```

При `false` приложение **не** вызывает `create_all()` и **не** делает аварийные `ALTER TABLE` из `create_app()`. Схема должна полностью соответствовать Alembic. Для локальной разработки по умолчанию остаётся `true` (удобно, но схема может «разъехаться» с миграциями).

## 2. Секреты и стабильность мира

- **`SECRET_KEY`** — уникальный, не коммитить в репозиторий.
- **`SERVER_SALT`** — зафиксировать на всю длительность плейтеста. Смена соли **инвалидирует** все коды доступа и меняет процедурные аспекты мира.
- **`ADMIN_TOKEN`** — длинная случайная строка; доступ к `/admin/world` и `/admin/accounts?token=...`.

## 3. Версия и баланс

- Версия игры: `GET /api/version` → `game_version` (источник: `docs/GAME_VERSION`).
- Баланс подхватывается при старте из `server/data/balance/`. После правок JSON — перезапуск процесса.

## 4. Автосол

- В админке `/admin/world` можно включить автотик и интервал. Убедитесь, что один процесс приложения (в MVP планировщик не рассчитан на несколько воркеров с общим тиком).

## 5. Аудит API для отдельных игроков (опционально)

Для игроков, согласившихся на запись мутаций API:

- В `/admin/accounts` включите флаг **feedback / audit** для аккаунта (поле `feedback_audited` в БД).
- В таблицу `feedback_playtest_api_logs` пишутся вызовы мутаций (см. `server/app/services/feedback_playtest_audit.py`).

Не включайте без явного согласия; в лог может попадать превью тела запроса.

## 6. Что передать тестерам

- URL веб-клиента и кратко: «Создать пилота» → сохранить код → «Вход».
- Указать, что это **dev-MVP**: возможны сбросы БД, баги, несовместимость после обновлений.
- Канал обратной связи (чат, форма, issue).

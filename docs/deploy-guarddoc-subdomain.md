# GuardStar на guarddoc.ru: dev → боевой домен

Цель: один процесс GuardStar за nginx; для тестов — отдельный **инстанс PostgreSQL и `DATABASE_URL`**, не смешивая данные с другими сайтами на том же хосте (например `school.guarddoc.ru`). На `dev.*` можно зоветь плейтестеров без доступа к репозиторию.

Плейтест: в админке `/admin/accounts` у нужных аккаунтов включается **лог мутаций API** (таблица `feedback_playtest_api_logs`; не логируются частые GET-опросы, тела входа/регистрации режутся / маскируются). Периодически чистите или архивируйте строки и заранее проговорите условия с тестирующими.

## Что уже удобно в коде

- Запросы из браузера идут на относительные пути `/api/...` — смена хоста не требует правок фронта.
- Секреты и БД — из переменных окружения (`server/.env.example`).

## Как держать инфраструктуру

1. **Один** процесс приложения (gunicorn и т.п.) на `127.0.0.1:<порт>`.
2. **Nginx** — отдельный `server` на тестовый хост; при выходе в бой — второй `server` или второе имя в `server_name`, тот же `proxy_pass`.
3. Заголовки: `Host`, `X-Forwarded-For`, `X-Forwarded-Proto` — как обычно для Flask за прокси.

## Переменные на сервере (зафиксировать и бэкапить список)

- `DATABASE_URL` — без привязки к домену.
- `SECRET_KEY`, `SERVER_SALT`, при необходимости `ADMIN_TOKEN`.
- При появлении абсолютных ссылок вне кода — опционально `PUBLIC_BASE_URL=https://...` (пока не обязательно).

## Переезд на новый домен — чеклист

- [ ] DNS A/AAAA боевого имени на IP сервера.
- [ ] Nginx: vhost или доп. `server_name`, тот же upstream.
- [ ] Сертификат (certbot) на новое имя; редирект HTTP→HTTPS при необходимости.
- [ ] `nginx -t && systemctl reload nginx` (или эквивалент).
- [ ] Проверка: `/`, `/login`, `GET /api/health`, `GET /api/version`.
- [ ] Сохранённые ссылки `/admin/...?token=...` обновить вручную.
- [ ] Сессии: пользователи залогинятся заново на новом хосте (ожидаемо).
- [ ] Снимок/бэкап БД перед переключением, если на dev уже «живые» данные.

## Не смешивать без причины

- Не поднимать два инстанса на одну и ту же БД.
- Не задавать `SESSION_COOKIE_DOMAIN=.guarddoc.ru`, пока явно не нужен общий логин между поддоменами.
